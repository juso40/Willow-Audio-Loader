This is a [pyunrealsdk](https://bl-sdk.github.io/willow2-mod-db/) mod.

## Install

Unpack `blaudio.zip` into your games `Binaries/Win32/Plugins/sdk_mods/` directory.

## How to Use
This mod works both, standalone as a way for you to add new sounds, or as a library for other mods to build upon.  
In most cases you just want to install this mod and follow the instructions of whatever mod you want to use that has this mod listed as a requirement.  

The following information is mainly relevant for the mod devs that want to add new sounds for you to enjoy :)  

### Sound Manifests
To add new non replacing sounds you can use the `add_sounds/` folder in this mods directory!  
Inside `add_sounds/` you can create any amount of nested subfolders.  
The mod scans through the folders and searches for `.toml` files.  

Each `.toml` file describes a new Soundbank which can contain any number of audio events.  

The following snippet explains each field and its purpose:

```toml
namespace = "my_mod"
bank_name = "Weapons"

[[sound]]
name = "shot"
sound = "new_shot.mp3"          # Relative to this manifest
positioning = "perspective"    # Default: "3d"
routing = "sfx"                # Default: "sfx"
gain = 0                       # dB offset, from -96 to +12
loop = false                   # Repeat until stopped when true
# stop_event = "StopShot"      # Optional companion Stop event
```

This creates:

- `AkBank'Transient.my_mod.Weapons'`
- `AkEvent'Transient.my_mod.Weapons.shot'`
- `AkEvent'Transient.my_mod.Weapons.StopShot'`, if requested

Add another `[[sound]]` table for each Play event. Names must contain only ASCII letters, digits, or underscores and must not start with a digit. Play and Stop event names must be unique within a bank, ignoring case. 
Audio paths must be relative to their manifest and point to existing files. 


### Positioning

| Value | Behavior | Typical use |
| --- | --- | --- |
| `2d` | Non-positional playback without distance attenuation or the 2D panner. | UI, music, narration, and player-only feedback. |
| `2d_panned` | Non-positional playback with Wwise's 2D panner enabled. Centered by default. | Audio whose panning is configured separately. Selecting this mode does not pan it automatically. |
| `3d` | Spatialized, distance-attenuated playback that follows the emitter. This is the default. | NPC speech, footsteps, machinery, and other world sounds. |
| `3d_static` | Spatialized playback using the emitter's initial position. | A cue that should stay where it started. |
| `3d_no_attenuation` | Spatialized playback without a distance-attenuation curve. | Directional cues intended to remain audible at distance. |
| `3d_unspatialized` | Distance attenuation without direction-based spatialization. | Ambience that fades with distance without a directional image. |
| `perspective` | 2D in first person and 3D in third person. | Player voices and actor audio when the game sets `FirstOrThirdPerson` on the posting game object. |

`perspective` uses the game's switch value. It does not detect the camera automatically.

### Gain

Set `gain` to a decibel offset from **-96 to +12 dB**. Omitted or `0` leaves volume unchanged. Integers and fractional values are accepted.

```toml
[[sound]]
name = "LevelUp"
sound = ["level_a.wav", "level_b.wav"]
positioning = "perspective"
routing = "player_voice"
gain = +3                     # Use -3 to make it quieter
```

Gain applies once to the entire event, including all clips, switch branches, and both perspectives. It does not modify or normalize the source audio. Positive gain can cause clipping, so start with small adjustments. Game bus volumes, attenuation, and callout settings still apply.

### Looping

Set `loop = true` to repeat the selected clip until stopped. Omitted or `false` plays it once. Wwise handles repetition on its own. Posting the event again starts another instance.

```toml
[[sound]]
name = "GeneratorHum"
sound = "generator_hum.wav"
positioning = "3d"
loop = true
stop_event = "GeneratorHum_Stop"
```

`stop_event = "GeneratorHum_Stop"` creates a separate `AkEvent` in the same bank. It contains a native Wwise Stop action and no media. It can stop a loop or a long one-shot sound.

Post the companion through `Actor.PlayAkEvent`, `blaudio.play`, or another normal `AkEvent` consumer. 
**Use the same actor or game object that posted the Play event.** It immediately stops all instances of that sound on that emitter without affecting other sounds or emitters.


### Selection trees

An `AkEvent` is a playback instruction, not necessarily one recording. Wwise can choose a clip at post time using a pool or switch tree.

```toml
[[sound]]
name = "level_up"
positioning = "perspective"
routing = "player_voice"
[sound.sound]
clips = ["level_a.wav", "level_b.wav", "level_c.wav"]
selection = "random"           # "random", "shuffle", or "sequence"
weights = [3, 2, 1]             # Positive integers, omitted for sequence
avoid_repeat = 1                # Default: 1 for random/shuffle, 0 for sequence
scope = "game_object"           # Or "global" to share this pool's history

[[sound]]
name = "callout"
[sound.sound]
group = "FirstOrThirdPerson"
default = "ThirdPerson"
[sound.sound.branches]
FirstPerson = "callout_fp.wav"
ThirdPerson = { clips = ["callout_a.wav", "callout_b.wav"] }
```

A `sound = ["a.wav", "b.wav"]` array is shorthand for a default pool. Pools contain only clips. Switch branches may contain clips, pools, nested switches, or `{ silent = true }`. Use `kind = "state"` to read a global state rather than an emitter switch. A tree can have at most 65,535 non-silent nodes and a maximum depth of 16. Perspective positioning shares media between its two copies of the tree.

Routing selects an existing game bus:

- `sfx` is the default sound-effects route.
- `voice` uses the base dialogue route.
- `player_voice` uses the player-dialogue route and honors `Player_CallOuts`.


## Python API

Use `add` for automatic IDs, bank loading, and Unreal object creation:

```python
from blaudio import SoundPool, add, play

result = add(
    {
        "shot": SoundPool(["shot_a.wav", "shot_b.wav"]),
        "reload": "reload.mp3",
    },
    namespace="my_mod",
    bank_name="Weapons",
    positioning={"shot": "perspective", "reload": "2d"},
    gain={"shot": -3},
)
play(result.events["shot"])
```

`namespace`, `bank_name`, and the sound names follow the manifest's naming rules. IDs are allocated for the current game session, not fixed across restarts.

`positioning`, `routing`, `looping`, and `gain` each accept a global value or a dictionary keyed by sound name. Missing overrides use `3d`, `sfx`, `False`, and `0` respectively. `stop_events` maps Play names to companion Stop names.

```python
from blaudio import add, play, stop

result = add(
    {"hum": "generator_hum.wav", "click": "click.wav"},
    namespace="my_mod",
    bank_name="Machines",
    looping={"hum": True},
    stop_events={"hum": "StopHum"},
)
play(result.events["hum"])
# Later, stop this event on every emitter with a linear fade:
stop(result.events["hum"], fade_ms=250)
```

## Runtime limits

- Changing the audio or settings of an already loaded named bank requires a game restart.
- ID collision checks cover loaded `AkObject` IDs and blaudio's reservations. They cannot see unloaded game banks or arbitrary internal nodes loaded by other mods.
- New media is embedded in memory. There is no disk-streaming support. PCM memory use depends on duration, sample rate, and channel count. One minute of 44.1 kHz stereo 16-bit PCM is about 10.1 MiB.
